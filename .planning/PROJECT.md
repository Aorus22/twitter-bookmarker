# Twitter Bookmarker

## What This Is

Twitter Bookmarker is a Chrome Extension (Manifest V3) plus a small local Go HTTP server that lets a single user categorize tweets on `https://x.com/i/bookmarks`. Clicking a category on a bookmarked tweet extracts the tweet metadata and appends it to a per-category CSV file under `~/.twitter-bookmarker/`. Optionally, the tweet is removed from X Bookmarks after the CSV write is confirmed.

It is not a bookmark manager, database, dashboard, or viewer. Its only job is: X Bookmarks → categorize → append metadata to CSV → optional unbookmark.

## Core Value

A categorized tweet is durably persisted to CSV before anything else happens — CSV is the source of truth, and nothing is ever unbookmarked from X before the CSV write succeeds.

### Out of Scope

Explicitly excluded by the PRD (do not re-add):

- Dashboard, search, filtering, CSV viewer/editor from the extension — not core to the categorize→CSV job
- Move tweet between categories, undo, import, export — adds state the CSVs already own
- Cloud sync, multi-device sync, authentication, accounts, remote backend — single-user local tool
- Quoted tweet text, media URLs, image/video download — only parent text is persisted
- Keyboard shortcuts, category icons, favorites, automatic/AI classification — not required for MVP
- Official Twitter/X API — the extension works off the rendered DOM only
- Support for pages other than `/i/bookmarks`, legacy `twitter.com`, or mobile browsers
- Database/queue/worker/Docker/Kubernetes infrastructure — a single Go process with an in-memory index is sufficient

## Context

- Single user, personal use, Linux + Chrome/Chromium.
- Backend runs manually (`twitter-bookmarker-server`); no systemd service, no auto-start, no auto-start from the extension.
- X is an SPA, so route changes and infinitely loaded timeline rows must be handled with `MutationObserver`.
- X DOM structure is unstable; all selector logic must be encapsulated in one extractor module.
- Category definitions and settings live only in `chrome.storage.local`; the backend never owns them.

## Constraints

- **Tech stack**: Chrome Extension Manifest V3, TypeScript, plain DOM APIs, no frontend framework; Go backend using `net/http` and `encoding/csv`.
- **Persistence**: CSV files under `~/.twitter-bookmarker/`; `index.json` is a rebuildable derived cache only.
- **Security**: Backend binds `127.0.0.1` only; filename must match `^[a-z0-9][a-z0-9-]*\.csv$`; no arbitrary paths; no shell command construction from request values.
- **Identity**: A Tweet Status ID may exist only once globally across all CSV files.
- **Performance**: Index fetched once per Bookmarks page entry; saved lookup is O(1) via an in-memory `Set<TweetID>`; no observers per tweet, no full-document scans per mutation.
- **Simplicity**: No database, no infrastructure beyond the extension + Go server + CSV + derived JSON index.

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Tweet Status ID as global duplicate key (not full URL) | Usernames can change; status IDs are stable | — Pending |
| Backend never stores categories or settings | Keeps backend stateless re: user config; extension owns config | — Pending |
| Rename changes only the extension's filename config | Old CSV data must never be lost or migrated implicitly | — Pending |
| Delete removes the category from storage only | CSV data and global index entries must survive | — Pending |
| CSV write is synchronous under a global write mutex | Guarantees no pending unpersisted bookmark on shutdown | — Pending |
| Index persistence failure does not fail a save | CSV is authority; index is rebuildable derived data | — Pending |
| `saved_at` is generated by the backend in UTC | Backend is the authority for persistence time | — Pending |
| Unbookmark only after HTTP 201 | Protects against data loss when the CSV write fails | — Pending |
